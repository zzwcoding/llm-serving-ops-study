# 0013 调参实验②:显存水位(阶段 3.2)

## 三问(阶段动机)

```
✅ 3.1 砍上下文  ✅ 3.2 显存水位(你在这里)  ⬜ 3.3 限并发  ⬜ 3.4 前缀缓存
```

- **这阶段干嘛的:** 把 `--gpu-memory-utilization` 从 0.92 降到 0.6,看 KV 缓存和并发能力怎么缩。
- **什么需求逼的:** 真实场景里一张卡常常不只跑一个服务(比如再塞个 embedding 模型)。你得学会"主动少占地",把显存让出来。
- **解决了什么麻烦:** 理解 vLLM 显存预算的完整公式,会算"让出 X 成显存,代价是多少并发"。

## 全链路一览

```
--gpu-memory-utilization 0.6(vLLM 只圈 60% 的地)
   │
   ▼
23.52 GiB × 0.6 ≈ 14.1 GiB 可用
 − 3 GB 权重(雷打不动)
 − ~2 GB 杂项
 ≈ 9 GiB 给 KV 缓存(原来 18.2 GiB,直接腰斩)
   │
   ▼
车位变少 → Maximum concurrency 跟着腰斩
```

类比:商场原来 92% 面积做营业区,现在只拿 60% 出来——
收银台(权重)不能动,仓库(杂项)不能动,砍的全是营业面积(KV 缓存)。

## 跟着数据走

1. Ctrl+C 停服务,加参数重启(这次**保留** 3.1 的 `--max-model-len 4096`,只动一个变量——做实验的基本功)
2. 新日志里找:`Available KV cache memory` 和 `Maximum concurrency`
3. **先预测:** 可用显存 14.1 GiB,减权重减杂项,KV 缓存大概多少?并发大概多少?
4. 对答案,验证"预算腰斩 → 并发腰斩"

## 新技术点四要素

**--gpu-memory-utilization(显存水位线)**
- 名字:vLLM 启动参数,0~1 的比例
- 作用:vLLM 圈地时"最多圈总显存的几成"。默认 0.9/0.92——**默认就奔着独占整卡去**,这是为生产独占部署设计的
- 参数:调低 → 让地给别的进程,KV 缓存和并发能力同比缩水;调高到逼近 1 → 极限榨取,但有 OOM 风险
- 用法:本项目挂载点——`vllm serve ... --gpu-memory-utilization 0.6`

## 关键顿悟

- **权重和杂项是"固定成本",KV 缓存是"可变成本"。** 砍预算砍的永远是可变成本。
- **一次只动一个变量。** 3.1 的 4096 保留,只改水位——否则数据变了你不知道是哪个参数的功劳。
- **共卡部署的核心就是这笔账。** 两个模型一张卡:各自水位设多少、各损失多少并发,全靠这个公式算。
