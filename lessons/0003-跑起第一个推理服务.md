# 0003 跑起第一个推理服务(阶段 1.1)

## 三问(阶段动机)

```
✅ 0.环境准备  ✅ 1.跑起服务(你在这里)  ⬜ 2.监控  ⬜ 3.调参  ⬜ 4.压测  ⬜ 5.量化与K8s
```

- **这阶段干嘛的:** 装 vLLM,把 Qwen2.5-1.5B 这个小模型变成一个 HTTP 服务。
- **什么需求逼的:** 模型文件本身只是硬盘上一堆数字,谁也用不了;推理引擎把它变成"随叫随到的服务"。
- **解决了什么麻烦:** 从此任何程序(你的 Agent、网页、App)都能通过标准接口调用模型。

## 全链路一览

```
模型文件(HuggingFace 上的一堆权重,3GB)
   │  vllm serve 下载 + 加载
   ▼
vLLM 引擎(把权重搬进显存,启动推理循环)
   │  对外开一个 8000 端口
   ▼
HTTP 服务(OpenAI 兼容接口,谁都能来调)
```

## 跟着数据走

命令:`HF_ENDPOINT=https://hf-mirror.com HF_HUB_DISABLE_XET=1 .venv/bin/vllm serve Qwen/Qwen2.5-1.5B-Instruct 2>&1 | tee vllm-boot.log`

1. vLLM 拿到模型名 → 去 HuggingFace(走国内镜像)下载权重 → 存进 `~/.cache/huggingface`
2. 权重从硬盘搬进显存(下一课会看到:3GB 权重 + 18GB 缓存包场)
3. 打印 `Application startup complete.` → 服务上线,占着终端不走(前台运行)

**捣乱一次(真实发生):** 第一次没带 `HF_HUB_DISABLE_XET=1`,下载直接 401 挂掉。原因:HF 新的 xet 下载协议走自家专用服务器,镜像站代理不了。关掉它,退回传统下载,镜像生效。

## 新技术点四要素

**vLLM(推理引擎)**
- 名字:vLLM,UC Berkeley 开源,业界事实标准
- 作用:模型文件 → HTTP 服务。两大核心技术:PagedAttention(像物业划车位一样管理显存,下一课细讲)、continuous batching(请求随到随插,不用凑满一班车才发车)
- 参数:`vllm serve <模型名>` 最小形态;`--port` 端口;`--max-model-len`、`--gpu-memory-utilization` 留给 Phase 3
- 用法:本项目挂载点——`~/work/.venv/bin/vllm serve ...`

**uv(快的 pip)**
- 名字:uv,Astral 出的 Python 包管理器
- 作用:装包比 pip 快几十倍,自带虚拟环境管理
- 参数:`uv venv .venv` 建独立包仓库;`uv pip install --python .venv/bin/python <包>` 往里装
- 用法:不 activate、用完整路径调用——脚本化部署更可靠,不会"忘了自己在哪个环境"

**国内镜像条件反射(运维高频)**
- Python 包:`pip install -i https://mirrors.aliyun.com/pypi/simple/ <包>`
- HF 模型:`export HF_ENDPOINT=https://hf-mirror.com` + `export HF_HUB_DISABLE_XET=1`
- Docker Hub:`daemon.json` 配 registry-mirrors(见 0002)

## 关键顿悟

- **报错从下往上读。** 最上面是"谁被连累",最底下才是"谁闯的祸"——401 那条就是这么挖出来的。
- **"卡住"和"在干活"要分清。** 管道会吞掉下载进度条;开第二个窗口 `du -sh ~/.cache/huggingface`,数字在涨 = 活着。
- **服务窗口和操作窗口分离。** 窗口1 跑服务看日志,窗口2 发请求做验证——这是日常工作的标准姿势。
