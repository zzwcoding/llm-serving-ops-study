# 阶段 0.1~0.2:GPU 云主机与显卡面板

## 这一步干嘛的
本机(Mac mini)无 NVIDIA 显卡,vLLM 必须 CUDA,故租用云 GPU 作为学习机;
并学会读 `nvidia-smi` 面板——排障第一扇窗。

## 为什么需要这么设计(解决了什么问题)
- 买卡成本高,按小时租用最经济(4090 约 ¥1.5~2/h,关机不计费)
- 推理服务出问题时,90% 的第一手信息来自显卡面板:显存爆了?利用率打满?僵尸进程占卡?

## 新概念四要素

### CUDA
- 名字:Compute Unified Device Architecture,英伟达 GPU 通用计算平台
- 作用:让 GPU 做通用计算(矩阵运算)。LLM 推理底层全是 CUDA;AMD / Apple Silicon 没有 CUDA,这是 vLLM 跑不了的根因
- 参数:无(平台非工具);报错常客 `CUDA out of memory` = 显存不够
- 用法:对我们透明,装 PyTorch/vLLM 时选对应 CUDA 版本即可(驱动 CUDA 13.0 是上限,向下兼容)

### nvidia-smi
- 名字:NVIDIA System Management Interface,GPU 自带命令行监控工具
- 作用:显卡的任务管理器——型号、显存占用、利用率
- 参数:`-l 2` 每 2 秒刷新(盯服务);`--query-gpu=memory.used --format=csv` 脚本取值
- 用法:直接敲 `nvidia-smi`

## 面板关键字段速查

| 字段 | 含义 | 排障用法 |
|---|---|---|
| Memory-Usage | 显存已用/总量 | 起服务后看权重+KV cache 占了多少 |
| GPU-Util | 计算利用率 | 持续 100% = 算力瓶颈,该扩容 |
| Processes | 谁在占卡 | 服务起不来先查僵尸进程 |
| Temp / Pwr | 温度/功耗 | >85C 警惕降频;P8=空闲档,P0=满载档 |

## SSH 免密连接(Mac → GPU 机)

三步配好,之后 `ssh gpu` 直达:

```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519   # 1. 生成密钥对(私钥留本机,公钥可分发)
ssh-copy-id -i ~/.ssh/id_ed25519.pub -p 30724 root@<主机>  # 2. 公钥装到服务器 authorized_keys
# 3. ~/.ssh/config 加别名:
# Host gpu / HostName <主机> / Port 30724 / User root / IdentityFile ~/.ssh/id_ed25519
```

- 密钥登录后密码可改(`passwd`),不影响免密
- `ssh gpu "命令"` 可在本机直接执行远端命令(脚本化/监控取值常用)

## 阶段 0.3:Docker + NVIDIA Container Toolkit

### 新概念

**Docker(容器引擎)**
- 作用:把应用+依赖环境打包成镜像,到处运行结果一致;推理服务生产环境 100% 容器化
- 关键命令:`docker run`(起容器)/ `docker ps`(看运行中的容器)/ `docker pull`(拉镜像)

**NVIDIA Container Toolkit**
- 作用:容器默认隔离、看不见宿主机显卡;这个工具包是 Docker↔GPU 的桥,提供 `docker run --gpus all` 参数
- 配置:`nvidia-ctk runtime configure --runtime=docker` 会写 `/etc/docker/daemon.json` 注册 nvidia runtime

### 翻车与解决(重要!)

**现象:** `service docker start` 报成功,但 dockerd 实际崩溃,日志:
`iptables ... Permission denied`

**根因:** 租来的实例本身就是个容器(PID 1 = tini),没有 NET_ADMIN 权限,
Docker 默认要建 iptables NAT 规则做桥接网络 → 权限被拒 → 启动失败。

**解法:** 关掉 iptables/桥接,容器改用宿主机网络:

```bash
# /etc/docker/daemon.json
{ "runtimes": {...nvidia...}, "iptables": false, "bridge": "none" }
# 手动起 daemon(无 systemd 环境):
nohup dockerd > /var/log/dockerd-manual.log 2>&1 &
# 起容器时加:--network host
```

代价:容器没有独立网络命名空间,端口直接占用宿主机端口——学习场景完全够用。

### 操作记录

```bash
curl -fsSL https://get.docker.com | bash -s docker --mirror Aliyun   # 装 Docker(29.7.2)
# NVIDIA Container Toolkit(1.20.0):nvidia.github.io 官方 apt 源
```

### 翻车升级:Docker 在此实例上不可用(三次闯关实录)

| 关卡 | 报错 | 缺的权限 | 结果 |
|---|---|---|---|
| 1. 网络 | `iptables ... Permission denied` | CAP_NET_ADMIN | ✅ `daemon.json` 加 `"iptables": false, "bridge": "none"` 绕过 |
| 2. 镜像解压 | overlayfs `mount: operation not permitted` | CAP_SYS_ADMIN | ❌ 尝试换 fuse-overlayfs(用户态文件系统)|
| 3. 起容器 | `unshare: operation not permitted` | seccomp 封锁 | ❌ **无解**,平台内核级禁止创建命名空间 |

**诊断命令(以后判断"这台机器能不能跑 Docker"直接用):**

```bash
cat /proc/1/comm              # tini → 你本身就在容器里
unshare -m true               # 失败 → 无法创建命名空间,Docker 没戏
grep Seccomp /proc/self/status  # Seccomp: 2 = 严格过滤模式
capsh --print | grep sys_admin  # 无 CAP_SYS_ADMIN
```

**结论:** 租用的 GPU 实例( gpuhome / AutoDL 类)是无特权容器,不支持嵌套 Docker。
计划调整:Phase 1 直装 vLLM 不受影响;Docker/K8s 概念在 Mac 上(Docker Desktop)学;
Phase 5 再评估换平台或用 minikube。

**附带收获:** 配置了 Docker Hub 国内镜像加速(daemon.json 的 `registry-mirrors`,
可用 `docker.1ms.run` / `docker.m.daocloud.io`)——以后在有权限的机器上还用得上。
